# V6实际工程模块 · v1.2.0

这三个入口直接迁移作者 V6 的场景代码。保留原镜头取景与平滑、人物位置和容器/内部裁切的独立插值、材质光照、流程汇聚与结果分层。原始文件哈希及改动范围见[来源清单](../assets/v6-modules/provenance.json)。不是依据截图重新猜出来的一套动效。

## 已移植范围

| 模块ID | V6原时间 | 模块时长 | 实际机制 |
|---|---|---|---|
| `presenter-reframe` | 10.30–12.80秒 | 2.50秒 | 原景全幅连续收为悬浮人物窗；外框与内部裁切分别过渡，字幕固定屏幕位置 |
| `workflow-merge` | 29.46–40.62秒 | 11.16秒 | 承接上一场景，三张不同深度的步骤卡逐项完成、汇聚，生成工具并停留供阅读 |
| `result-takeover` | 70.80–76.80秒 | 6.00秒 | 人物缩小退后并消失，结果页接管视野，标题实体层抬起后落定，保留编辑状态 |

这版未提供“完整97秒影片替换素材即复现”、反向回全幅独立入口、任意时长自动适配、竖屏自动重排或剪映/AE原生工程。内部保留部分V3/V4辅助代码及其他场景，用于原V6相机预计算和上一场景交接；只有上表三个范围作为公开模块维护。画面中的应用操作是流程示意，并非新产品的真实录屏证据。

原生60fps输出须取整帧：流程模块输出670帧，文件时长约11.1667秒；最后一帧仍处于11.16秒逻辑区间内。其余分别150、360帧。不要用拉伸人声强行适配这些固定时长。新口播时长或语义落点不同，应在新工程中调整动画事件与阅读停留并重新检查。

## 最快复现

先按[运行环境](runtime.md)安装或验证Agent Motion。在Skill文件夹运行：

```sh
node scripts/init-v6.mjs --engine "../lrh-agent-motion" --name sample-workflow --module workflow-merge --config assets/v6-modules/example-content.json
node scripts/render-v6.mjs --engine "../lrh-agent-motion" --project sample-workflow --out "../sample-workflow-output"
```

默认输出1280×720、60fps无声MP4，并保存首、中、末PNG与技术结果。`--width 3840`使用4K画布重新渲染图形。输出目录和工程名都必须全新，脚本拒绝覆盖。也可选择另外两个模块并省略`--config`先看原标签。

工程保留在引擎的`work/sample-workflow/`。从引擎根目录运行`node serve.mjs`，打开终端显示的本地地址后访问`/work/sample-workflow/`，可播放和拖动。`index.html`是预览入口，`config.json`是素材/文案配置，`core/scene-v6.js`是动效源码。工程依赖该引擎，不是随处双击HTML即可运行的离线网页。

## 换自己的素材

```sh
node scripts/init-v6.mjs --engine "../lrh-agent-motion" --name my-workflow --module workflow-merge --input "自己的口播.mp4" --start 18.5 --config "本期文案.json"
node scripts/render-v6.mjs --engine "../lrh-agent-motion" --project my-workflow --out "../my-workflow-output" --width 3840
```

`--start`表示原视频截取起点，脚本提取该模块所需时长。输入不足会报错；不复制尾帧假装素材够长。素材按比例缩放并补边到3840×2160，然后提取60fps帧序列；低清源放大和30fps复制帧不会新增真实细节。竖屏源虽然可以补边导入，仍须另行重排才能得到合适的横屏构图。

可选`--mask "保护遮罩.mp4"`接收与原片同时间轴的灰度视频：白色保护原人物色彩，黑色允许背景调色。脚本将灰度变为alpha，保持同一截取起点。它不会自动完成抠像；应使用已经核实的同步遮罩。没有遮罩时保留原片全部色彩，不能宣称与V6人物保护调色完全一致。

创建和渲染均不复制、生成或混入音频。这是视觉模块包；本期原声、BGM、动作音效在主工程另行对齐混音。原作者人声、音乐、原片、保护遮罩和参考成片没有随包发布。

## 文案、字幕与人物位置

`--config`接收JSON，仅包含`text`、`captions`与`framing`。使用[替换文案示例](../assets/v6-modules/example-content.json)开始修改。该示例字幕用于11.16秒流程模块，不要直接传给2.5秒人物模块。

```json
{
  "text": {"PPT Master":"演示稿助手", "项目汇报":"方案展示"},
  "framing": {"centerX":1920, "centerY":985},
  "captions": [
    {"start":0, "end":2.0, "text":"让结果成为画面主角"},
    {"start":2.0, "end":6.0, "text":"停稳之后再阅读和编辑"}
  ]
}
```

此例用于`result-takeover`。字幕使用模块内部秒数，必须排序、互不重叠且不超过模块时长，单条不超过30字符。文本只支持[配置契约](../assets/v6-modules/config.mjs)列出的字段，字段有长度上限；超限必须改文案或在工程中重新排版，不能任意压扁字形。长度检查不能代替真实字体及手机尺寸的可读性检查。

`framing`的中心坐标是**素材规范化为3840×2160之后**的人物取景中心，默认沿用参考。换人、机位或源比例后，定位面部与上身并修改中心，检查整个过渡及停稳状态是否切头、卡脖子或偏位。两个参数只调整人物窗口中的取景，不重新安排全片布局，也不是逐帧人脸跟踪。

`config.json`也可直接修改后重新导出。`media.type=sequence`引用本工程的JPEG帧与可选PNG保护遮罩；生成器会填好帧数和60fps。`reference-sequence`仅用于原时间轴的同源回归，不是制作新口播的默认入口。路径只能指向本地服务中的相对/根路径，不接受远程URL和目录穿越。

## 如何判断复现成功

同一素材、遮罩、文案、字体、时序和运行环境下，先比较原实现与移植实现的对应帧和完整动作。换机器后仍需确认字体、浏览器与GPU差异；不保证所有平台像素完全相同。换口播后检查人物完整性、中文排版、语义落点、阅读停留和实际音轨，新内容不继承原作品的用户验收。

仓库提供`scripts/compare-v6.mjs`供持有原工程者在本地执行：验证原源码哈希，以相同输入驱动两套页面，逐帧比较PNG，并在差异时保存本地证据。默认遍历三个范围的1180帧；`--stride 60 --width 3840`可补充4K抽样。它不下载私人原工程，也不上传输入和差异图。公开发布的技术验证范围见仓库`VALIDATION.md`。

修改文字和图片后的程序通过、源码一致、GPU渲染成功都不等于已经完整看过/听过成片。必要的完整视听尚未执行时，只能称待检查预览。
